# Engineering Notes

## Spatial Inputs

보행 데이터는 선형 도로와 버퍼 도로로 구성합니다. 선형 도로와 노드 연결 정보는 경로 탐색에 사용하고, 도로 양쪽으로 2m씩 확장한 버퍼는 그림자 면적을 계산하는 데 사용합니다. 거리·면적 연산에 쓰는 건물, 도로, 그림자 레이어의 좌표계는 `EPSG:5179`입니다.

현장실습에서 누락되거나 0인 건물 높이를 보정할 때는 층수에 3.5m를 곱하는 추정식을 사용했습니다. 현장실습 기록에는 특정 업무용 건물에 층고 4.2m를 적용한 사례도 있습니다. WKT 형상은 QGIS와 Python에서 처리할 수 있도록 GeoPackage와 Shapefile로 가공했습니다. 입력 파일과 재현 범위는 [QGIS & Shadow Preprocessing](qgis-workflow.md)을 참고하세요.

## Shadow Geometry and Aggregation

오목한 ㄷ자·ㄴ자 건물에 볼록 껍질(Convex Hull)을 적용하면 건물 사이의 빈 공간까지 채울 수 있습니다. 잔상 기법(Shadow Ghosting)은 원래 건물 형상을 태양 반대 방향으로 조금씩 옮긴 뒤 합집합합니다.

~~~text
L = h / tan(α)
dx = −L × sin(θ)
dy = −L × cos(θ)
~~~

`h`는 건물 높이, `α`는 태양 고도, `θ`는 방위각입니다. 이동 거리를 7구간으로 나눠 원래 위치를 포함한 8개 형상을 계산합니다. 태양 고도가 0° 이하면 그림자 형상을 만들지 않으며, 양수일 때 길이 계산에 사용하는 고도의 하한은 0.1°입니다. 이동 간격이 건물 폭에 비해 크면 형상 사이에 빈틈이 생길 수 있습니다. [그림자 생성 코드](../scripts/preprocessing/generate_shadows.py)

도로 버퍼별 그늘 비율은 해당 시간대의 건물 그림자와 도로 버퍼가 겹친 면적을 도로 버퍼 면적으로 나눈 값입니다. `legacy-sum`은 현장실습 노트북처럼 건물마다 교차 면적을 합산하므로 그림자가 겹치면 같은 면적을 여러 번 셀 수 있습니다. 전처리 스크립트의 기본 `union`은 교차 형상을 합집합한 뒤 면적을 계산합니다. [집계 코드](../scripts/preprocessing/aggregate_shadow_by_link.py)

| 데이터 모델 | 대표 필드 | 용도 |
| --- | --- | --- |
| `HOURLY_SHADOW` | `build_id`, `time_slot`, `shadow_geometry` | 그림자 형상 보관·공간 시각화 |
| `HOURLY_LINK_STAT` | `link_id`, `time_slot`, `shadow_ratio` | 링크·시간대별 그늘 비율을 경로 비용에 반영 |

공간 교차 연산은 사전에 수행합니다. 앱은 공개 CSV를 읽어 도로 그래프에 링크·시간대별 그늘 비율을 결합합니다. 이 CSV는 `legacy-sum`과 부동소수점 정밀도 범위에서 일치하는 현장실습 통계입니다. 이 설계의 실행 시간이나 메모리 개선 폭은 별도로 측정하지 않았습니다. [전처리 비교 기록](qgis-workflow.md#reproduction-checks)

## Route Costs

Kakao 장소 검색 좌표는 `EPSG:4326`에서 `EPSG:5179`로 변환합니다. SciPy KDTree로 가장 가까운 도로 노드를 찾아 NetworkX 그래프의 시작점과 끝점으로 사용합니다. 실제 출입구나 도로 횡단 가능성은 이 과정의 평가 범위 밖입니다.

최단 경로의 기준은 링크 길이의 합입니다. 쿨링 비용은 링크 길이에 가중치를 곱해 계산합니다. 가중치에는 그늘 부족, 실내 구간, 보행 시설, 강수량에 따른 페널티가 포함됩니다. 개인화 비용은 그늘 선호도와 지하 통로·보도육교·실내 구간 회피 설정을 반영합니다. 후보를 탐색할 때는 최단거리 대비 사용자가 정한 우회율을 적용합니다. [비용과 후보 탐색 코드](../src/coolingpath/routing.py)

현장실습에서는 [Melnikov et al. (2022)](https://doi.org/10.1038/s41598-022-06383-5)이 연구 조건에서 관찰한 그늘 구간의 상대 거리 비용 0.86을 참고했습니다. 당시 사례의 예상 이동 시간 +14%는 프로젝트에서 정한 탐색 한도입니다. [현장실습 시뮬레이션](evaluation.md#internship-route-comparison)

## Route Metrics

| 지표 | 계산 또는 표시 기준 |
| --- | --- |
| 거리 | 경로에 포함된 도로 링크 길이의 합 |
| 예상 이동 시간 | 기본 보행 속도 1.2m/s와 실내 구간·횡단보도·육교·강수 조건을 반영한 추정값 |
| 평균 그늘 비율 | 링크별 그늘 비율의 길이 가중 평균 |
| 그늘 보정 온도 | `기온 − 길이 가중 평균 그늘 비율 × 5℃`로 계산한 자체 비교 지표 |
| 상대습도·시설 정보 | 기상 데이터의 상대습도와 경로에 포함된 보행 시설 개수 |

그늘 보정 온도는 경로 비교를 위한 시뮬레이션 값입니다. 온도 차트는 선택 시각의 경로 그늘 비율을 고정하고 시간별 기온에 적용합니다. 강수량이 0보다 크면 모델은 해당 경로 계산에서 그늘 비율을 0으로 적용합니다. 실내 구간과 터널의 기본 그늘 비율은 1로 설정합니다. [지표 계산 코드](../src/coolingpath/metrics.py)

## Weather and Demo

실시간 기상 모드는 출발지 좌표를 기준으로 Open-Meteo의 기온·강수량·상대습도를 조회합니다. 요청 제한 시간은 5초입니다. HTTP 상태와 배열 구조, 시각 중복, 기상값 범위를 확인한 뒤 실행 당일 08:00–19:00 KST에 해당하는 예보를 사용합니다. 오류가 발생하면 앱에서 나타나는 안내에 따라 폭염·강수 데모를 선택할 수 있습니다. [기상 조회와 응답 검증](../src/coolingpath/services.py)
